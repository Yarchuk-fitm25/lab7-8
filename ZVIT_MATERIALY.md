# Матеріали до звіту №7–8

**Тема:** Розробка та тестування моделей даних у Django та Flask.

**Мета:** навчитися створювати пов'язані моделі та міграції, виконувати ORM-запити й перевіряти вебдодатки за допомогою PyTest.

## Завдання 1. Моделі Django

Створила моделі `Course`, `Label`, `Task`, `TaskPlan` для обліку навчальних завдань. Предмет `Course` може мати багато завдань, тому використала `ForeignKey`. Одне завдання може мати кілька позначок, тому додала `ManyToManyField`. Окремий план виконання належить тільки одному завданню, тому застосувала `OneToOneField`. Для кожної моделі визначила поля, обмеження, сортування в `Meta` та метод `__str__`.

**Політики видалення:** видалення предмета із завданнями заборонено (`PROTECT`), щоб випадково не втратити записи; план завдання видаляється разом із ним (`CASCADE`), оскільки без завдання план не потрібний.

## Завдання 3. Flask-SQLAlchemy

У Flask створила моделі тієї самої предметної області, але з іншим синтаксисом SQLAlchemy. Зв'язок «багато-до-багатьох» організувала через таблицю `task_labels`, а інші зв'язки через зовнішні ключі та `relationship`. Для SQLite використала адресу `sqlite:///planner.db`. У Flask-Migrate є дві ревізії, як і в Django.

| Критерій | Django | Flask |
|---|---|---|
| Міграції | Вбудовані команди `makemigrations`, `migrate` | Додаткова бібліотека Flask-Migrate |
| Початкове налаштування | Папка міграцій у додатку | Потрібне середовище Alembic |
| Застосування | `manage.py migrate` | `flask db upgrade` |
| Перегляд стану | `showmigrations` | `flask db current` |
| Файли | `planner/migrations` | `migrations/versions` |

## Завдання 6. HTTP-тести

За допомогою тестових клієнтів перевірила головну сторінку, список завдань, відсутню сторінку та форму додавання. Для GET-запитів перевіряла статус `200` і вміст сторінки, для відсутнього об'єкта `404`, для правильного POST `302`. При неправильному POST форма повертається з помилками і статусом `200`. У Flask для тестового додатка вимкнула лише перевірку CSRF, щоб тестові POST-запити працювали без браузера.

| Маршрут | Сценарій | Очікуваний статус |
|---|---|---|
| `/` | GET, позитивний | 200 |
| `/tasks/` | GET зі списком, позитивний | 200 |
| `/tasks/9999/` | GET відсутнього об'єкта, негативний | 404 |
| `/tasks/add/` | POST правильних даних | 302 |
| `/tasks/add/` | POST без потрібних полів | 200 із помилками |

## Завдання 7. Моки та покриття

Для зовнішньої залежності підмінила реальне надсилання повідомлення мок-об'єктом. Це дозволяє тестувати виклик без поштового сервера. Для внутрішньої залежності підмінила функцію визначення поточного року, щоб не залежати від дати на комп'ютері. Перевірила виклики моків через `assert_called_once_with`. Покриття отримую командою `pytest --cov`.

| Колонка coverage | Значення |
|---|---|
| Stmts | Кількість виконуваних рядків коду |
| Miss | Рядки, які не виконалися під час тестів |
| Cover | Частка покритих рядків у відсотках |
| Missing | Номери непокритих рядків |

**Непокриті модулі та відсотки:** [Заповнити після фактичного запуску coverage, не вигадувати].
